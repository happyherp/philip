# Plan: Conversation Condensation for Long Chats

## Context

Philip sends the **full conversation history** from the browser on every turn. The server prepends a system prompt and uses Anthropic's `cache_control: ephemeral` breakpoints to cache the conversation prefix (TTL ≈ 5 min). This works well for short/active chats, but for long conversations where the cache has gone cold, every turn pays full price for potentially thousands of prompt tokens.

The goal: when a conversation is **both long (over a token threshold) and the cache has expired** (> 5 min since last request), summarize the history using a cheap model. The summary replaces the old messages, and subsequent turns build on top of it.

## How the summary is stored between turns

The browser owns the conversation (localStorage). When condensation triggers:

1. The **server** generates the summary and streams the normal LLM response as usual.
2. The server also sends an SSE event back to the client: `{condensed: {summary: "...", upToIndex: N}}`.
3. The **client** stores `condensedSummary` and `condensedUpToIndex` alongside its existing conversation state in localStorage. The full `messages` array is kept intact for display/scroll-back.
4. On subsequent turns, the client sends only `messages.slice(condensedUpToIndex)` plus the `condensedSummary` string — **not** the full history. This keeps payloads small.
5. The **server** receives the summary + recent messages and assembles the LLM history as:

```
system: [Philip's system prompt]                  ← cache_control: ephemeral
user:   "[Conversation summary]\n{summary text}"  ← cache_control: ephemeral
assistant: "Understood, let's continue."
...all messages since the condensation point...
```

### Re-condensation

There is no fixed "recent message count." Everything since the last condensation is sent to the LLM. If that accumulation grows past the token threshold again and the cache has expired, the server re-condenses: it summarizes `[previous summary + all messages since]` into a fresh summary, sends it back, and the client updates its stored `condensedSummary` and `condensedUpToIndex`.

### Client-side localStorage shape

```javascript
{
  id: "abc123",
  messages: [/* all messages, kept for display */],
  condensedSummary: "USER FACTS:\n- ...\nVERSES DISCUSSED: ...",  // null if never condensed
  condensedUpToIndex: 42,   // messages[0..41] are captured in the summary
  lastRequestAt: 1719000000000,  // updated after each chat turn
  // ...existing fields: title, summary, lang, createdAt
}
```

## Approach

### New module: `src/condense.ts`

Core logic, fully unit-testable with injected fetch:

| Function | Purpose |
|---|---|
| `estimateTokens(messages)` | Rough estimate: `totalContentLength / 4`. No tokenizer dependency. |
| `extractQuoteReferences(messages)` | Regex scan of assistant messages for `{{quote/q/ref REF @ID}}` markers. Returns deduplicated list of `"Book C:V[-V]"` strings. |
| `shouldCondense(tokenEstimate, lastRequestAt, threshold, cacheTtlMs)` | Returns `true` when estimate > threshold AND `Date.now() - lastRequestAt > cacheTtlMs`. |
| `buildCondensePrompt(lang)` | Prompt for the cheap summarizer — instructs it to output structured, compact summary with user facts, reading progress, and key discussion points. Explicitly tells it to preserve everything the user said about themselves. |
| `condenseHistory(messages, deps)` | Calls the cheap LLM, parses the summary, programmatically appends extracted quote references. Returns the summary string + the index it covers. |

**Summary format** (output from the cheap LLM + programmatic appendix):

```
USER FACTS:
- Name: Carlos
- From Belize
- Protestant background

READING PROGRESS:
- Reading Gospel of John, paused at 8:47

KEY POINTS:
- Interested in Greek word studies
- Discussed logos concept, light vs darkness

VERSES DISCUSSED: John 1:1-5, John 1:6-9, John 3:16, John 8:31-32
```

The "VERSES DISCUSSED" line is **not** generated by the LLM — it's extracted programmatically from `{{quote/q/ref}}` markers in assistant messages and appended by code. This is more reliable and token-efficient than having the LLM list them.

**Token reduction strategies built into the prompt:**
- Bullet points, not prose — ~60% fewer tokens than a narrative summary
- No verse text — only references (the model can call `get_passage` to re-fetch)
- Strip quote markers from the transcript before sending to the summarizer (they're verbose noise)
- Cap the summary prompt to instruct a tight format

### Modify: `src/chat.ts`

Add optional condense fields to `StreamChatOptions`:

```typescript
condenseModel?: string;         // cheap model for summarization
condenseThreshold?: number;     // token count threshold (default: 8000)
condenseCacheTtlMs?: number;    // cache TTL in ms (default: 300_000 = 5 min)
lastRequestAt?: number;         // unix timestamp of browser's last chat request
condensedSummary?: string;      // existing summary from a previous condensation
```

Before calling `runChat()`:

1. Build the effective history: if `condensedSummary` exists, prepend it as a `user`/`assistant` pair before the recent messages.
2. Estimate tokens on the effective history.
3. If `shouldCondense()` is true, call `condenseHistory()` → get new summary → use the condensed version for the LLM call → send `{condensed: ...}` SSE event back to the client.

The `send` callback (already used for `{token}`, `{lang}`, `{done}`) gains a new event type: `{condensed: {summary, upToIndex}}`.

### Modify: `functions/api/chat.ts`

- Read `body.lastRequestAt` (number) and `body.condensedSummary` (string) from the POST body.
- Read new env vars: `CONDENSE_MODEL` (default `anthropic/claude-haiku-4.5`), `CONDENSE_TOKEN_THRESHOLD`, `CONDENSE_CACHE_TTL_SECONDS`.
- Pass them through to `streamChatResponse()`.

### Modify: `public/frontend/state.js`

- Add `lastRequestAt`, `condensedSummary`, `condensedUpToIndex` to conversation state.

### Modify: `public/frontend/chat-client.js`

- Accept `lastRequestAt` and `condensedSummary` in opts, include in the POST body.
- Parse `{condensed: ...}` SSE events, call a new `onCondensed` callback.

### Modify: `public/app.js`

- Track `lastRequestAt = Date.now()` after each successful chat turn. Persist in localStorage.
- When building the outgoing message array, if `condensedSummary` exists, send only `messages.slice(condensedUpToIndex)` plus the summary string.
- Handle the `onCondensed` callback: store `condensedSummary` and `condensedUpToIndex` in state and persist to localStorage.

## Configuration defaults

| Env var | Default | Rationale |
|---|---|---|
| `CONDENSE_MODEL` | `anthropic/claude-haiku-4.5` | ~20x cheaper than Sonnet for a simple summarization task |
| `CONDENSE_TOKEN_THRESHOLD` | `8000` | ~32K characters ≈ well beyond the system prompt + a few turns |
| `CONDENSE_CACHE_TTL_SECONDS` | `300` | Matches Anthropic's ephemeral cache TTL |
